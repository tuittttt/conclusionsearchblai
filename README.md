# 剧集汇 / Conclusion Search

四个公开剧集目录的搜索、来源评分对比、资源导航与社区别名整理。

## 怎么更新数据（网站使用者）

1. 打开网站，点击顶部「手动更新数据」。不需要登录。
2. 等待显示更新结果，再看各来源的「最后成功采集」时间。
3. 每次点击都可发起更新，无需等待一小时；全站已有更新正在进行时，请等待它完成后再试。
4. 某来源失败会保留上次成功的数据，不会清空目录。

更新只执行普通 HTTP 请求与数据库操作，不调用 AI 模型。此 Sites 部署没有创建 AI 云任务或定时自动化。初始数据包含 479 条在云的背面种花记录、830 条甜度满分有效记录和 2407 条喵仔记录；后续数量以原站为准。

## 功能

- 全目录中英文及别名搜索，分页，来源筛选，按日期或原站最高评分排序。
- 严格英文名匹配，或在英文名不冲突时按完整中文名匹配；同一来源存在重名时不自动匹配。不是模糊猜测。
- 各来源评分人数和资源单独保留，不混算评分。
- 封面优先级：在云的背面种花、甜度满分、喵仔。图片加载失败时顺延。
- 公共累计跳转计数，计数不放在跳转按钮里。
- 无登录的别名提议和记录合并，2 个浏览器支持后生效。Cookie 去重不等于真人身份认证。
- 合并仅改变展示分组，不删除来源记录、链接或计数。

## 文件

- `app.js`：浏览器界面和分组展示。
- `index.html`：页面结构和样式。
- `worker/catalog.js`：来源适配、严格匹配、快照和更新流程。
- `worker/aliases.js`：提议与支持。
- `worker/index.js`：HTTP 及跳转入口。
- `source-seed.json`：初始来源快照；线上更新保存在 D1，正常更新不需要重新发布。
- `drizzle/`：有顺序的数据库迁移，已应用迁移不可改写。
- `scripts/build.mjs`：无依赖构建脚本，Node 22+。
- `tests/`：隔离测试，不向线上提交测试别名或虚假支持。

## 开发

```bash
node scripts/build.mjs
node tests/catalog-workflow.mjs
node tests/alias-workflow.mjs
```

`alias-workflow.mjs` 使用 Python 标准库 SQLite，不需要第三方数据库包。
不要把 `.git`、账户凭据、Cookie、私人数据写入源码或源码压缩包。

## 部署到自己的 Cloudflare（不使用 AI 云任务）

1. Cloudflare 中打开 Workers & Pages，创建应用并连接此 GitHub 仓库。
2. 项目名使用 `conclusionsearchblai`，构建命令填 `npm run build`，部署命令填 `npm run deploy`。
3. Wrangler 会自动创建 D1，部署脚本随后执行数据库迁移。等整个流程成功后再打开网址。
4. 第一次打开网站时，点击「手动更新数据」检查四站状态。

此 GitHub 版本部署到你自己的 Cloudflare 后，会启用普通 Cron，按北京时间 00:00、06:00、12:00、18:00 直接执行同步代码，不调用 AI、不需要 AI API key。Cloudflare 资源仍受其套餐配额限制。

本地也可执行 `npm install`、`npx wrangler login`、`npm run build`、`npm run deploy`。

注册、登录与 GitHub 仓库授权由你本人在官方网页完成。不要把密码、API token 或环境文件提交到公开仓库。当前 ChatGPT Sites 试用站仍为手动更新，独立部署后的 Cron 不会影响它。

独立部署将创建新数据库；旧试用站的点击数和社区提议不会自动迁移，需要另外核对迁移。

## 来源与边界

仅通过原站网页自身使用的公开目录、公开评分接口读取元数据，不访问管理后台、不登录第三方账户、不搬运视频。第二站和第四站没有验证可用的剧集深链，所以保留复制原站剧名再打开的方式；资源入口可从本网展开查看。

项目代码采用 MIT。第三方海报、站名、剧名、资源与评分数据的权利仍归原权利人。本仓库不声称拥有这些内容，也不对它们重新授予 MIT 许可。

## 评分与标签筛选

在筛选栏填写最低评分（5 分制，包含边界值），或选择标签。来源、收录日期、评分和标签必须由同一条原站记录同时满足；暂无评分不会满足最低分。点击「清除筛选」可恢复全部。各来源的类型及公开标签显示在其记录下，保留各站命名。

第一个来源的公开 `/tags` 接口随目录一起更新；接口暂时不可用时保留已有标签，恢复后自动补充。第二个来源采集 tags、styles、country，第三个来源采集公开 tags、genre、country、year；不采集 hiddenTags。

## 第四个来源 PageVII

公开目录接口为 `https://www.pagevii.com/api/data`。采集已公开剧目的中英文名、别名、发布日期、原站评分和人数、分类标签、封面及可用资源入口，不读取评论或管理接口。封面优先顺序为第一站、第二站、第三站、PageVII。第一次部署后手动更新即可导入；之后随每次手动更新或既有六小时定时同步更新。

第二个来源仅保留明确标注 OBL、OGL、BL、GL、LGBT/LGBTQ 等类别的剧目；排除 BG/OBG 和未标明相关类别的记录。该规则同时应用于历史快照和新采集数据，其他来源不受此规则影响。

筛选区分为来源/日期与其他条件两行。收录日期为包含边界的起止范围，结束下拉框默认「同一天」，只选一次日期即可查当天；可选「至今」或一个具体结束日期来查范围。标签按原站折叠分组；可添加手动标签关键词（按回车或「添加」），多个标签按任意一个匹配，原站标签限定该来源，手动标签词在所有来源中作包含搜索。

## 社区拆分

「一起整理剧名」可展开待确认和已通过的提议。在已归并的剧集卡片中选择「别名 / 合并 / 拆分」，再选「拆分：它们不是同一部剧」及另一条来源记录。依据选填，包含提交者在内两个浏览器支持后生效。已通过的拆分优先于自动匹配及合并提议，阻止两条记录再次直接或间接归并；不删除记录、评分、链接或点击数。已通过的提议在剧集卡片中隐藏，仍可在底部历史列表查阅。

部署需执行 `npm run deploy`，以应用追加的 `0003_split_proposals.sql` 数据库迁移。旧别名、合并与投票记录保持不变。

第二站评分同时读取 main 目录和 guest_social 独立评分快照（支持 gzip 压缩），新评分优先，接口故障时保留已有可用评分。第一站完整评分接口失败后重试一次，重试等待上限 35 秒。仅保留评分数值和人数，不发布社交快照中的评论。第二站有资源时展示醒目的直接打开按钮；该按钮跳转网盘资源，并非原站剧集详情页。

`flower-rating-backup.json` 为公开评分接口的数值快照，仅含剧名、平均分与人数，不含评论或昵称。当第一站采集端遇到服务错误时，快照仅补充暂无评分的记录，并在来源状态中标注快照日期；不会覆盖正常接口或已有历史评分。接口恢复后，正常同步数据优先。

## 可选账号与云端收藏

无需邮箱，使用用户名和至少 8 位密码注册。未登录可继续本地收藏，并可在提醒中勾选「不再提示」（仅当前浏览器）。登录后自动合并当前浏览器的收藏，其他浏览器登录同一账号即可同步；退出登录不会删除云端收藏，也不会把账号收藏复制给匿名访客。注册时请保存恢复码；忘记密码可用用户名、恢复码及新密码重设，重设后旧会话与旧恢复码失效。

账号数据存放于现有 Cloudflare D1，不依赖邮件服务。密码使用独立随机盐和 PBKDF2-SHA256（100000 次）保存，数据库不保存明文密码；会话令牌以哈希保存，Cookie 使用 HttpOnly、Secure、SameSite=Lax、__Host 前缀，最长 30 天。接口校验同源请求，限制登录/注册/恢复尝试次数。必须用 `npm run deploy` 部署，以自动应用 `0004_accounts.sql` 迁移。
